# Putting `~/rounds-codex-ios` under version control

Written 2026-09-14. **Run these on the Mac, one at a time.** A pasted block's last line does not
execute — no trailing newline — and this project has been bitten by that before.

## Why

The Capacitor project exists only on your Mac. Everything a session can see about the native build
is inference from reference copies in `native/ios-project/`, and those reference copies **have never
been compiled**. Two of them were wrong when checked on 2026-09-14:

- `capacitor.config.json` carried `"contentInset": "always"` — the exact setting that puts headers
  under the Dynamic Island on every cold load. It cost a debugging session to find the first time.
- `App.entitlements` claimed `roundscodex.com` and `rounds-codex.netlify.app` are the same Netlify
  site. They are two different sites.

Both are fixed now, but the real cure is that the files Xcode builds from are the files in a repo.
Then `verify_universal_links.js` can check the entitlement instead of printing "not checkable".

## What goes in, and what must not

**In:** the Capacitor project — `capacitor.config.json`, `package.json`, `ios/App/*.xcodeproj`,
`ios/App/App/Info.plist`, `App.entitlements`, the app icons, any Swift you have added.

**Out:** `www/` is **generated** by `scripts/build_native_payload.js` and is ~826 MB. It must never
be committed — it would blow the repo up and it is derived from the deploy repo anyway. Same for
`Pods/`, `DerivedData/`, `build/` and `node_modules/`.

## Step 1 — check the size before you commit anything

```
du -sh ~/rounds-codex-ios ~/rounds-codex-ios/www 2>/dev/null
```

If the project minus `www` is more than ~50 MB, stop and tell me what is large — something is in
there that should not be.

## Step 2 — write the ignore file

```
cat > ~/rounds-codex-ios/.gitignore <<'GITIGNORE'
# The web payload is GENERATED by scripts/build_native_payload.js in kreithen/rounds-codex and is
# ~826 MB. Never commit it. `npx cap sync ios` copies it into ios/App/App/public, which is why that
# is ignored too -- both are build output, not source.
www/
ios/App/App/public/

# CocoaPods and SPM build products
Pods/
*.xcworkspace/xcuserdata/
*.xcodeproj/xcuserdata/
*.xcodeproj/project.xcworkspace/xcuserdata/
.swiftpm/

# Xcode build output
DerivedData/
build/
*.ipa
*.dSYM.zip
*.xcarchive

# Node
node_modules/

# macOS
.DS_Store
GITIGNORE
```

## Step 3 — see what would be committed, BEFORE committing

```
cd ~/rounds-codex-ios && git init -q 2>/dev/null; git add -An . | head -60
```

Read that list. If `www/` or `Pods/` appears, the ignore file did not take — stop and tell me.

## Step 4 — check the total again, against what git would store

```
cd ~/rounds-codex-ios && git add -A && git status --short | wc -l && du -sh .git
```

## Step 5 — commit

```
cd ~/rounds-codex-ios && git commit -qm "The Capacitor project as it actually builds today" && git log --oneline -1
```

## Step 6 — push

Make a **private** repo. This carries your team ID and bundle configuration; it is not a secret in
the credential sense, but it is not public-repo material either, and `rounds-codex` is public.

```
cd ~/rounds-codex-ios && git remote add origin https://github.com/kreithen/rounds-codex-ios.git && git branch -M main && git push -u origin main
```

Tell me when it is pushed and I will `add_repo` it, read what actually ships, and extend
`verify_universal_links.js` to check the fifth link in the chain instead of reporting it as a gap.

## What I will do once it is in

1. Compare the real `App.entitlements` with `native/ios-project/App.entitlements` and say plainly
   which is right — that settles the Universal Links question, which is currently unresolved.
2. Compare the real `capacitor.config.json` against `"contentInset": "never"`, which the safe-area
   fix depends on and which nothing has ever verified against the shipped project.
3. Fold both into `preflight.sh ios`, so an archive cannot go out with either of them wrong.
